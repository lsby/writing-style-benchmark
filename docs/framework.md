# 题目、引擎和实现

源码保留三块。`questions/` 定义题目，分为 `article/`、`rewrite/`、`dialogue/`；`implementations/` 根据作者和写作任务返回参考文本；`engine/` 加载资料，顺序调用答题和评分 API，直接保存独立基线。

## API 用法

每个实现目录都提供 `run.ts` 和 `mcp.ts`，分别导出运行入口类与 MCP 入口类。公共执行流程由 `src/implementations/base.ts` 中的入口基类承担，配置放在具体入口类里。普通导入不会执行任务；顶层 [src/run.ts](../src/run.ts) 显式创建选中的入口实例并运行，例如：

```ts
import { 向量运行入口 } from './implementations/vector-retrieval/run.js'

await new 向量运行入口().运行()
```

运行 `pnpm start` 或 `pnpm exec tsx src/run.ts`，也可以切换为全文方案的 `全文运行入口`。作者、题目及答题和评分 API 在对应实现的 `run.ts` 中填写，没有额外命令行参数。入口内部的引擎配置形式如下：

```ts
import { 测试引擎, 作者 } from '../../engine/index.js'
import 等待题 from '../../questions/article/W01.js'
import { 全文实现 } from './index.js'

let 引擎 = new 测试引擎({
  作者: [作者.朱光潜, 作者.张爱玲],
  题目: [等待题],
  实现: new 全文实现(),
  答题API: {
    地址: '', // 填写答题服务的 HTTP(S) 地址，可以包含 /v1。
    密钥: '', // 无需认证时明确留空。
    模型: '', // 填写该服务的模型标识。
    参数: { temperature: 0.7, max_tokens: 8192, seed: 42, reasoning_effort: 'low' },
    超时毫秒: 1_800_000,
  },
  评分API: {
    地址: '', // 独立填写评分服务。
    密钥: '',
    模型: '',
    参数: { temperature: 0, max_tokens: 4096, seed: 42, reasoning_effort: 'low' },
    超时毫秒: 1_800_000,
  },
})
console.log(await 引擎.运行())
```

地址、模型和密钥字段在类型中必填。构造引擎时检查两份配置：空地址、空模型和非法地址立即报错，此时尚未加载资料、创建基线目录或调用模型。上例的地址和模型留空，使用时需填写；仓库入口中的本地服务示例也应按实际环境调整。无需认证的 API 使用空密钥；密钥只进入请求头，不写入基线。

两份 API 配置互相独立，没有本地模型或复用另一份配置的兜底。每次请求独立，无跨题或答题历史；生成参数原样发送，框架不补温度或输出上限。模板里的参数可按服务支持情况修改、删除；超时未指定时采用 30 分钟的请求时限。

每个作者的每道题只生成一次作品，再以完整原文、题目、作品和评分标准请求独立评分。风格、质量、自然度沿用现有 1～5 分标准。字数问题和输出截断照实记录，生成失败或无效评分立即停止，已完成的题目和作品保留。无自动重试或恢复调度；重新运行会新建记录，同名目录拒绝覆盖。

评分提示词位于 `src/engine/evaluation/scoring.ts`。风格理由需结合参考原文与待评作品的具体措辞、典故或联想方式、表达质地；自然度会检查刻意点题、空泛升华和生硬回收意象的收尾。规则随原文判断，不要求所有作者用典或辞藻华丽，不按固定词语或句式扣分。评分仍使用原有三项 1～5 分及 observations 结构，不回写历史评分。

## 自定义实现与题目

方案统一继承 `参考实现`，提供 `名称`、`说明` 和 `获取参考文本(输入)`。输入为 `{ 作者, 写作任务 }`，返回 `string | Promise<string>`。作者只包含 `姓名` 和 `文章`，每篇文章只有 `标题`、`正文`。全文方案返回全部文章，检索或记忆方案自行挑选、组织参考内容。

实现返回的文本不包含模型消息的 `role`、`content` 结构，不负责追加题目或调用模型。API 引擎把参考文本与题目组织为统一的 system/user 消息，随后作答、独立评分和保存；所有实现共用相同的消息组织方式。API 和 MCP 在实现返回后统一添加参考作者姓名与资料说明，再交给模型或智能体。全文、向量与随机抽句方案使用相同的作者提示；实现只负责选择与组织原文，不自行重复添加作者提示。

每个实现目录的 `run.ts` 入口类继承 `基准运行入口`，`mcp.ts` 入口类继承 `MCP运行入口`；两者通过各自配置启动同一份参考实现。新增方案时补齐这两个文件，顶层入口只需引用所选类，无须维护中央实现列表。每个 MCP 入口只发布自己的实现；底层参考服务仍接受显式实例列表，列举与分派共用该列表。`src/implementations/index.ts` 只导出类和类型，导入它不会创建默认实例或启动任务。

### 向量检索方案

`vector-retrieval` 按中文句号 `。` 和英文句号 `.` 切分每篇原文。连续英文点（如 `...`）按省略号整体保留，不在其中断句；数字之间的小数点也不切分。保留句号、紧随句号的闭引号，以及句内的逗号、其他标点和空白；末尾没有句号的内容也保留，空片段跳过。不跨作者检索。原句和完整题目交给同一个本地向量模型编码，按余弦相似度取最高的 N 句作为参考，相同分数按原文顺序排列，候选少于 N 时全部返回。实现返回文本只包含空行分隔的原句，不附来源篇名或摘要；API 和 MCP 随后统一添加作者提示，与全文及随机抽句方案保持一致。

实现索引不提供默认向量配置。API 参数放在 `src/implementations/vector-retrieval/run.ts` 的运行入口类中，MCP 参数在同目录的 `mcp.ts` 入口类中独立填写。两个入口默认直接通过 Transformers.js 在 CPU 上加载 `Xenova/paraphrase-multilingual-MiniLM-L12-v2`，使用 fp32、均值池化和归一化，取 N=30；无需启动 LM Studio 或其他向量服务。首次取参考时下载模型到项目的 `.cache/embeddings/`，后续复用下载文件；普通导入和 MCP 列举实现都不会加载或下载模型。本地模型仅用于向量编码，MCP 写作仍由调用它的智能体完成。

也可将向量配置改为在线模式，使用 OpenAI 兼容的 `/v1/embeddings`。在线模式的地址、模型、密钥与答题、评分模型独立；文档和查询前缀应按所选模型要求填写。默认本地 MiniLM 模型不加前缀。

使用向量方案的 MCP 入口启动服务后，调用 `get_reference` 或 `start_writing` 时填写 `implementation: "vector-retrieval"`，之后仍用 `save_result` 保存。比较全文方案时，将顶层启动类切换到 `full-context` 对应入口，并将 MCP 调用中的实现名换成 `full-context`；结果继续使用同一基线格式，`reference.txt` 保存本次实际返回的参考。

作者原文的向量在实现实例内缓存，原文内容变化时重新编码；同一进程中换题只重新编码查询。原文向量缓存不写磁盘，重启后重新计算；本地模型的下载文件单独缓存在磁盘。模型返回错误、无效向量或维度不一致时立即报错，不自动改用全文。

本地模式用 tokenizer 核对输入长度，超长文本按模型上限分成连续的完整文本块，各块分别编码，再按有效 token 数加权平均并归一化，避免长题目被静默截断。短文本直接编码。这个聚合方式和本地模型配置一同记入运行记录。在线模式仍将完整输入交给所配置的服务，其长度限制由服务决定。

作者名称统一定义在 `src/engine/data/authors.ts` 的 `作者` 常量中，`作者姓名` 类型从它的值自动推导。入口用 `作者: [作者.朱光潜, 作者.张爱玲]`，编译器会提示可用项并拒绝无效姓名。新增作者先补充这份定义，再添加原文清单和目录标识。资料加载用同一枚举校验 CSV；MCP 的作者选项由加载成功的作者及目录标识生成。

题目直接 import 后放入数组，如 `[等待题, 读书题]`，数组顺序就是执行顺序。没有题号查询、默认题组或题目注册。每道题是一个 `写作题目` 实例，包含编号、标题、类型、要求和字数范围；直接传入引擎即可，不必注册或动态加载模块。TS 类型约束内部契约，模型响应在外部入口校验。

`article/` 中 W01～W08 是自由文章题，W09～W11 是技术文档题，覆盖命令行使用说明、异步任务接口接入和故障排查。技术文档题自带虚构规格，沿用 `article` 协议值；评分时另外关注规格准确性、步骤可执行性和异常处理。正文允许小标题、列表和代码块，字数仍按去掉首行标题后的非空白字符计算，包含命令及代码。

## 保存格式

新结果直接写入 `baselines/<UNIX毫秒时间戳>/`，目录名只包含时间戳。作者、题号、实现、模型和参数都写进元信息，不拼进目录名。同名目录直接报错，不覆盖已有结果。可用 `基线目录` 指定保存位置，用 `仓库目录` 指定原文资料根目录。

每题保存五个文件：

| 文件              | 内容                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| `reference.txt`   | 统一添加作者提示后的参考文本，保留实现原文的空白与换行                 |
| `question.json`   | 完整题目、题号、类型和篇幅要求                                         |
| `output.txt`      | 答题模型返回的原始正文                                                 |
| `evaluation.json` | 评分与理由，未完成时为 `null`                                          |
| `metadata.json`   | 作者、题号、实现、时间、API 配置、实际模型、消耗、字数检查、状态和错误 |

`reference.txt` 保存统一作者提示和本次实现实际选择或组织的参考内容：全文方案会包含全部选文，检索方案则保存检索结果。不额外复制原文目录，不保存完整请求或响应，也不生成额外报告、CSV 或校验文件。重新运行需要仓库里的作者原文；评分标准与裁判提示词一起定义在 `src/engine/evaluation/scoring.ts`，不再读取外部标准文件。历史基线全部保留原目录及原内容，不转换旧格式。

新结果还会记录实现的非敏感配置、运行代码版本与内容指纹、实际加载语料的 SHA-256，以及评分标准和实际请求消息的指纹。向量方案记录嵌入模型、检索数量、批量大小、前缀与超时等参数；随机抽句记录抽取数量和随机种子。实现通过 `导出配置()` 提供非敏感配置；基类默认返回 `null`，表示自定义实现未提供配置。全文方案返回空对象。随机抽句未指定种子时，在创建实例时生成并记录有效种子，同一实例使用该种子抽句。密钥不得加入导出的配置。这些字段位于 `metadata.json` 的 `provenance`：`code` 记录 `commit`、`dirty`、`sha256`，`datasetSha256` 标识实际加载的语料，`scoringSourceSha256` 标识评分标准源码，`implementationConfig` 保存实现配置。代码信息取自运行源码所在目录，与可单独指定的语料目录分开；无法读取 Git 信息时，提交号与修改状态为 `null`。`writerMessagesSha256`、`judgeMessagesSha256`、`judgeSchemaSha256` 分别记录实际答题消息、实际评分消息与评分 JSON 格式的 SHA-256，在请求前保存。尚未发生的请求为 `null`。指纹用于识别版本变化；重现运行仍需保留对应代码、语料和模型。

作答和评分分别记录输入文本字符数、输出文本字符数、token 和耗时。字符按各条消息正文的 Unicode 字符求和，包含空白和标点，不含协议包装；token 使用服务实际返回值，缺失为 `null` 或省略。密钥不保存。

`metadata.json` 的 `checks` 使用 `passed`、`characterCount`、`issues` 记录通过状态、正文字数和问题列表。`status` 为 `running`、`complete` 或 `failed`；错误写进 `error` 字段。失败立即停止，已经生成的正文及可取得的消耗继续保留，未完成正文为空文本、未完成评分为 `null`。所有状态都只写这五个文件；实现返回后立即保存 `reference.txt`，后续 API 或评分失败也会保留。

## MCP 入口

`pnpm mcp` 启动 stdio 服务，提供 `list_implementations`、`get_reference`、`start_writing` 和 `save_result`。智能体作答后由服务保存到固定的 `baselines/`，不调用模型或评分。工具参数及接入方式见 [MCP 说明](mcp.md)。
