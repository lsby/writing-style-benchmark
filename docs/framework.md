# 框架整体逻辑

本项目围绕“参考生成—自动作答—独立评分—基线归档”的流程构建，源码由三大核心模块组成：

- `questions/`：定义写作题目，分为自由文章与技术文档（`article/`）、改写（`rewrite/`）、对话（`dialogue/`）。
- `implementations/`：参考实现层。根据指定作者与写作任务筛选或组织原文参考文本，不负责拼装最终提示词或调用模型。
- `engine/`：测试引擎与评测层。负责加载作者语料、统一组织消息、顺序调用答题与评分接口，并将结果保存为独立基线。

## 核心运行流程

框架支持 **API 自动评测** 和 **MCP 智能体接入** 两种模式，两者共享同一套参考实现与基线存储格式：

### 1. API 自动评测

各实现目录下的 `run.ts` 继承 `src/implementations/base.ts` 中的运行入口基类，在入口内配置作者、题目、实现以及相互独立的答题 API 与评分 API。顶层 [src/run.ts](../src/run.ts) 显式创建所选入口实例并启动（`pnpm start`）：

1. **校验与加载**：构造引擎时先校验两份 API 配置，随后加载对应作者的原文语料。
2. **获取参考**：针对每道题目，调用当前实现的 `获取参考文本` 方法得到参考内容，并由框架统一补充资料说明，不附加作者姓名或标识。
3. **独立作答**：将参考文本与题目组织为统一的消息格式发送给答题 API，生成作品并执行字数等基础检查。每次请求独立，不保留跨题上下文。
4. **独立评分**：基于 `src/engine/evaluation/scoring.ts` 中的标准，将完整原文、题目与生成作品发送给评分 API，从风格、质量、自然度三个维度独立打分并给出理由；评分提示同样不附加作者身份。
5. **落盘与中断策略**：每个步骤完成后立即落盘。若生成失败或评分无效则立即停止，已完成的题目和作品会保留，重新运行会新建基线目录而不覆盖历史记录。

### 2. MCP 接入

各实现目录下的 `mcp.ts` 继承 `src/implementations/base.ts` 中的 MCP 入口基类，通过 `pnpm mcp` 启动 stdio 服务，向外部智能体暴露 `list_implementations`、`get_reference`、`start_writing` 和 `save_result` 工具。外部智能体获取参考文本并自行完成写作后，通过 `save_result` 将结果直接保存至基线目录；MCP 模式不负责调用模型或执行自动评分。具体接入方式见 [MCP 说明](mcp.md)。

## 扩展与配置

- **新增参考实现**：继承 `参考实现` 基类并实现参考文本提取逻辑（以及可选的非敏感配置导出），在实现目录中提供 `run.ts` 和 `mcp.ts`，再于顶层 [src/run.ts](../src/run.ts) 或 [src/mcp.ts](../src/mcp.ts) 中引用即可，无需修改引擎核心。
- **维护作者与题目**：作者列表统一定义在 `src/engine/data/authors.ts` 中，增删作者需同步维护对应语料清单；题目以独立实例形式在入口中按需组合传入，引擎按数组顺序依次执行。

## 基线保存格式

每次运行在 `baselines/<时间戳>/` 下创建独立目录，按题目保存五个文件：

| 文件              | 内容                                                             |
| ----------------- | ---------------------------------------------------------------- |
| `reference.txt`   | 统一添加资料说明后的参考文本（不附加作者身份）                   |
| `question.json`   | 完整题目、题号、类型与篇幅要求                                   |
| `output.txt`      | 答题模型或智能体返回的原始正文                                   |
| `evaluation.json` | 评分结果与理由（MCP 模式或未完成时为 `null`）                    |
| `metadata.json`   | 作者、题号、实现、消耗统计、字数检查、状态及版本指纹（不含密钥） |
