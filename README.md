# Writing Style Benchmark

## 为什么做这个项目？

如今的大模型已经渗入各类写作场景，但主流模型就那么几个，写出来的文字很容易陷入千篇一律的“AI 腔”——比如高频出现的“不是……而是……”“不能直接说明”“稳稳地把你托住”“轻轻推你一下”等句式。这些句子单看没有语法毛病，读多了却容易审美疲劳。

为了探索如何让 AI 写出不同风格、更有辨识度的文字，首先需要一套客观的比较基准。本项目准备了真人作家的原始作品和涵盖多种场景的测试题，测试不同方案提取和还原文风的实际效果。

## 项目概览

- **语料库（`data/`）**：收录鲁迅、朱光潜、张爱玲、钱钟书、汪曾祺、老舍六位作家的 54 篇独立选文，以及维特根斯坦的《逻辑哲学论》，共七位作者、55 篇作品。
- **测试题库（`src/questions/`）**：覆盖文章写作、对话与改写等多种场景，并专门设计了虚构技术文档类题目，用于考察作者文风在严格技术准确性与操作约束下的表现。
- **参考方案（`src/implementations/`）**：每个实现包含自己的 `run.ts` 和 `mcp.ts` 入口类及配置，继承 `base.ts` 中的公共入口基类。顶层 [API 入口](src/run.ts) 和 [MCP 入口](src/mcp.ts) 只导入选中的类并显式启动；扩展方式见 [框架说明](docs/framework.md)。
- **基线归档（`baselines/`）**：每次运行按时间戳保存题目、参考文本、模型输出、评分结果与元信息，便于复现与对比。

## 使用

为了同时兼顾自动评测与日常订阅制客户端的使用场景，项目将“文风参考方案”与“运行方式”解耦，提供两条路径：

### 1. API 自动跑分（基准对比）

适合对比不同文风生成方案或不同模型的客观表现。运行后引擎会按顺序执行：

`获取参考文本 → 组装提示词 → 调用答题 API 生成内容 → 调用评分 API 逐题打分 → 保存基线结果`

```powershell
pnpm install
# 在 src/run.ts 选择入口类，在对应实现的 run.ts 中配置作者、题目与 API
pnpm start
```

### 2. MCP 服务（接入智能体 / 日常写作）

如果你使用的是 Codex 等订阅制 AI 客户端，没有独立的 API 调用权限，但客户端支持 MCP，可以直接将本项目作为 MCP 服务挂载：

```powershell
pnpm mcp
```

接入后，既可以配合智能体完成基准测试并保存结果，也可以直接在日常对话中要求 AI 用指定作家的风格进行写作，AI 会自动调用工具获取参考文本。详见 [MCP 说明](docs/mcp.md)。

例如，向量方案的参数位于 `src/implementations/vector-retrieval/run.ts` 和 `mcp.ts`。切换到全文方案时，只需将顶层入口引用改为 `full-context` 对应的入口类；每个 MCP 服务只发布该入口选中的实现。
